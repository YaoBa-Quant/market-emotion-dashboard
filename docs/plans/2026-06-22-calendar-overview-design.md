# 日历总览页设计

日期: 2026-06-22
项目: `market-emotion-dashboard`
状态: 已确认，可进入实施拆分

## 1. 背景

当前页面本质上是“某个交易日的详情页”:

- 默认展示最近一个交易日的完整情绪详情
- 支持通过日期切换查看历史某一天
- 不具备月度视角，也无法直接看出哪些交易日已缓存、哪些交易日未抓取

新增“日历总览页”的目标是:

- 提供交易日级别的月度概览
- 让用户快速定位某一天的情绪分数、建议仓位和开仓状态
- 明确显示“交易日但后台尚未抓取”的日期
- 支持点击未抓取日期后触发拉取，并进入详情页
- 通过趋势图补充区间级别的沪深300与仓位走势

## 2. 页面结构

采用双页面结构，但仍基于现有单页应用，以 URL 查询参数区分页面类型。

### 2.1 页面入口

- 默认入口: 最近交易日详情页
- 页面参数:
  - 详情页: `/?page=detail&date=YYYYMMDD`
  - 日历页: `/?page=calendar&month=YYYYMM`
- 不引入 `vue-router`
- 继续使用 `window.history.pushState` 与 `popstate`

### 2.2 详情页

保留现有详情页主体，仅补充页面级导航:

- 顶部增加一级切换:
  - `详情`
  - `日历总览`
- 当前页默认为 `详情`
- 点击 `日历总览` 跳转到当前详情所属月份的日历页
- 详情页继续保留交易日选择器

### 2.3 日历页

日历页分为两个区域:

- 上半区: 月历卡片视图
- 下半区: 区间趋势图

顶部包含:

- 页面切换入口: `详情 | 日历总览`
- 月份切换: `上月 / 本月标题 / 下月`
- 返回最近交易日详情按钮

## 3. 日历卡片设计

### 3.1 每日格子展示字段

对于“已缓存或已成功抓取”的交易日，格子展示:

- 日期
- 情绪分数
- 建议仓位
- 开仓状态:
  - `可开仓`
  - `暂停`

### 3.2 每日格子状态

定义四种状态:

1. `non_trading`
   - 非交易日
   - 置灰
   - 不可点击

2. `ready`
   - 交易日且已有缓存摘要
   - 可点击
   - 点击后进入详情页

3. `missing`
   - 交易日但无缓存
   - 显示 `待获取`
   - 可点击
   - 点击后触发后台拉取，再进入详情页

4. `error`
   - 交易日但拉取失败
   - 显示 `获取失败`
   - 可再次点击重试

### 3.3 样式建议

- `ready`:
  - 可根据情绪分数或开仓状态着色
  - 推荐以开仓状态为主，情绪分数为辅
- `missing`:
  - 黄灰色底
  - 展示 `待获取`
- `error`:
  - 浅红底
  - 展示 `重试`
- `non_trading`:
  - 浅灰底

## 4. 趋势图设计

### 4.1 图表目标

在日历页展示区间趋势，帮助用户从月度/季度角度理解:

- 沪深300走势
- 建议仓位走势

### 4.2 图表形式

- 折线图双轴
- 左轴: `HS300`
- 右轴: `建议仓位 (%)`
- 默认范围: 最近 3 个月
- 支持切换:
  - `1月`
  - `3月`
  - `6月`
  - `1年`

### 4.3 联动行为

- 图上每个点对应一个交易日
- 点击点可跳转到详情页
- 若该交易日尚未缓存，则先触发抓取再跳转

## 5. 后端接口设计

不复用现有详情接口去硬拼月历数据，新增两个摘要型接口。

### 5.1 月历概览接口

路径:

- `GET /api/market/calendar/summary?month=YYYYMM`

返回目标:

- 某月自然日和交易日状态
- 每个交易日是否已缓存
- 已缓存时返回日历格需要的摘要字段

返回结构建议:

```json
{
  "month": "202606",
  "monthLabel": "2026年6月",
  "latestTradeDate": "20260622",
  "days": [
    {
      "date": "20260601",
      "isTradeDate": true,
      "status": "ready",
      "cached": true,
      "emotionScore": 86.2,
      "suggestedPosition": 80,
      "allowOpen": true,
      "regimeLabel": "Risk-On"
    },
    {
      "date": "20260623",
      "isTradeDate": true,
      "status": "missing",
      "cached": false
    },
    {
      "date": "20260628",
      "isTradeDate": false,
      "status": "non_trading",
      "cached": false
    }
  ]
}
```

### 5.2 趋势接口

路径:

- `GET /api/market/calendar/trend?range=3m`

返回目标:

- 区间内交易日的趋势序列
- 至少包含:
  - `tradeDate`
  - `hs300Close`
  - `suggestedPosition`
  - `emotionScore`
  - `allowOpen`

返回结构建议:

```json
{
  "range": "3m",
  "startDate": "20260323",
  "endDate": "20260622",
  "series": [
    {
      "tradeDate": "20260622",
      "hs300Close": 5059.66,
      "suggestedPosition": 90,
      "emotionScore": 88.5,
      "allowOpen": true
    }
  ]
}
```

### 5.3 按日抓取接口

路径:

- `POST /api/market/emotion/fetch`

请求体:

```json
{
  "date": "20260618"
}
```

返回行为:

- 若缓存已存在，直接返回成功及摘要
- 若未缓存，则调用现有历史抓取逻辑生成快照并写库
- 抓取成功后前端跳转到详情页

返回结构建议:

```json
{
  "ok": true,
  "date": "20260618",
  "cacheStatus": "created",
  "summary": {
    "emotionScore": 84.3,
    "suggestedPosition": 70,
    "allowOpen": false
  }
}
```

## 6. 数据来源与复用策略

### 6.1 不新增新数据源

当前版本只保留历史模式，因此新增日历页仍完全基于历史快照体系:

- 交易日历: 继续使用 `listCompletedTradeDates()`
- 单日详情: 继续使用 `getMarketEmotionDashboard()`
- 本地缓存: 继续使用 `market_emotion_snapshots`

### 6.2 摘要数据生成策略

日历页摘要不单独建新表，第一版推荐按现有快照直接派生:

- 已缓存日期:
  - 从 `market_emotion_snapshots` 读取 `snapshot_json`
  - 提取 `emotionScore`
  - 提取 `suggestedPosition`
  - 提取 `allowOpen`
  - 提取 `regimeLabel`
- 未缓存交易日:
  - 通过交易日历判断为交易日
  - 但 `market_emotion_snapshots` 中不存在对应记录
  - 标记为 `missing`

后续若性能不足，再考虑增设摘要表。

## 7. 前端实现建议

### 7.1 路由状态

在现有 URL 管理逻辑基础上新增:

- `page`
- `date`
- `month`

建议规则:

- 详情页以 `date` 为主
- 日历页以 `month` 为主
- 页面切换时保留上下文月份或日期

### 7.2 组件拆分建议

从当前 `App.vue` 中拆出:

- `DashboardDetailPage.vue`
- `DashboardCalendarPage.vue`
- `CalendarMonthGrid.vue`
- `CalendarTrendChart.vue`
- `TopPageSwitch.vue`

`App.vue` 只负责:

- 读取 URL 状态
- 页面切换
- 共享的加载、跳转与错误处理

### 7.3 用户交互

- 从详情页点 `日历总览`
  - 进入当前详情所在月份
- 从日历页点击 `ready`
  - 直接进入对应详情页
- 从日历页点击 `missing`
  - 先请求抓取接口
  - 成功后进入详情页
- 从日历页点击 `error`
  - 再次触发抓取

## 8. 错误与加载策略

### 8.1 月历加载失败

- 保留页面框架
- 提示“该月摘要加载失败”
- 提供“重试”按钮

### 8.2 单日补抓失败

- 日期格标记为 `error`
- 弹出失败原因
- 不跳详情页

### 8.3 趋势图数据缺口

- 若某些日期未缓存，可跳过这些点
- 若区间整体数据不足，显示“样本不足”

## 9. 默认入口结论

采用已确认方案:

- 默认打开最近交易日的详情页
- 在详情页顶部提供 `日历总览` 一级入口
- 从日历页提供“返回最近交易日详情”入口

原因:

- 详情页是主结果页，打开即用
- 日历页承担导航、回溯、补抓和整体观察
- 用户心智更稳定

## 10. 实施顺序

建议按以下顺序开发:

1. 新增 `page/date/month` URL 状态管理
2. 拆出详情页组件，保证现有详情页无回归
3. 新增月历概览接口
4. 新增日历页基础 UI 和月份切换
5. 新增单日补抓接口
6. 接入 `missing/error` 状态点击行为
7. 新增趋势接口
8. 接入 `HS300 + 仓位` 趋势图
9. 补充空态、错误态和返回路径体验

## 11. 风险点

- 月历页一次性读取整月多日快照，需注意读取效率
- 趋势图区间过长时，建议后端直接返回摘要序列，不要前端遍历所有详情
- 若未来继续增加页面，当前查询参数路由可能不如 `vue-router` 清晰

## 12. 第一版范围边界

第一版只做:

- 双页面切换
- 月历摘要展示
- 交易日缺失识别
- 点击缺失日触发补抓
- HS300 与仓位趋势图

第一版不做:

- 实时模式
- 多市场指数切换
- 自定义评分口径
- 用户级书签或多视图偏好存储
